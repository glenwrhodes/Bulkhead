# Bulkhead: notes for agents

A C++20 / DirectX 12 / DXR first-person shooter in a generated sci-fi ship maze. The plan and
milestone status are in `docs/PLAN.md`; update that table when a milestone lands.

## How work is verified on this machine

- Bash can only run `cmake` and `ctest`. Build and test with:
  - `cmake -S . -B build -G "Visual Studio 17 2022" -A x64`
  - `cmake --build build --config Release`
  - `ctest --test-dir build -C Release --output-on-failure` (labels `unit`, `smoke`, `film`,
    `bench`, `package`). Run `-L film` in pieces: each walk half takes about 5 minutes to
    render and 3.5 to check. `-R <name>_check` also reruns its `_run` unless you add
    `-FS <name>`.
- The download: `.github/workflows/build.yml` builds on GitHub (no GPU there: unit tests
  plus the CPU-only `--check` of the zip), and publishes a release on every push to master.
  `ctest -L package` does the same unpack-and-run check here, plus a ray-traced capture.
- Nobody watches the screen. Each feature must be visible in a headless capture
  (`Bulkhead.exe --capture <dir>`), run as a ctest test. Open the resulting PNGs with the Read
  tool and look at them before calling a build good.
- The game is filmed for a YouTube video. Keep Blender `.blend` sources in `art/blender/` so
  they can be filmed, and add `film`-labelled capture tests for new features.
- The user launches the interactive window themselves; do not launch it.
- The orchestrator commits after each round; git is not available to agents here.

## Blender kit

- The kit is generated by scripts in `art/blender/scripts/`. Edit the scripts, not the
  `.blend`, then run `bk_build.main()` in Blender (MCP). It rebuilds every piece, exports
  `assets/*.glb` plus `assets/kit_manifest.json`, and saves `art/blender/bulkhead_kit.blend`.
  Placement conventions (cells, edges, canonical orientations, door leaf nodes) are in
  `art/blender/README.md`.
- After `importlib.reload`, reload `bk_core` first; the other modules import from it.
- Materials use backface culling, so a wrongly oriented face shows as a hole in renders.
  From outside, a corridor reads as a cutaway: items on the near wall seem to float. That's expected.
- A Blender viewport screenshot (`bpy.ops.screen.screenshot`) only shows view changes made in an
  earlier MCP call, because the viewport redraws after a call returns. Don't minimise Blender:
  its screenshots go black.

## Engine notes

- Rendering is an inline ray tracer (`shaders/trace.hlsl`, RayQuery, cs_6_5). The design is
  in `docs/PLAN.md` (Rendering).
- glTF fronts are counter-clockwise in right-handed space. Do **not** set
  `D3D12_RAYTRACING_INSTANCE_FLAG_TRIANGLE_FRONT_COUNTERCLOCKWISE`: with it, primary rays
  cull every front face and the level renders inside out.
- World space: X east, Y up, Z south. Maze cell (x, y) is centred at (4x, 0, 4y). Kit
  pieces are rotated with `Mat4::rotationY(yawFor(dir))`; see `src/world/Level.cpp`.
- Headless modes: `--capture` (the walk as PNGs), `--shots` (RT on/off pairs at fixed
  viewpoints), `--bench` (window-mode frame times in `bench.log`), `--overhead`.
  The window itself can't be watched here: `--bench` is how window-mode quality (noise,
  ghosting) and speed get checked. ctest `bench_static` (label `diag`) holds the camera
  still to check that accumulation converges.
- Never pack integers into float render targets with `asfloat()`: small integers become
  denormals, and the store flushes them to zero. (This silently broke temporal
  accumulation once.) Store `float(id)` instead.
- Don't leave Blender's viewport in Rendered mode while capturing: it competes for the GPU.
- A ctest run in the foreground is cut off after 10 minutes, and background runs after
  another 10. The 40 × 40 ship's 1080p walk (~6000 frames at 12 spp, ~0.08 s each) is split
  into `film_walkthrough_a` and `_b`; run them with separate ctest commands.
- Ship moods (lit, dim, dark, derelict) live in `src/world/Sections.*`. They use their own
  `Rng` streams: never draw from the maze's stream for them, or every layout changes.
  The derelict dressing in `Level.cpp` has its own stream too.
- Effects (sparks, steam, bolts, scorch marks) are computed from time, not simulated, so
  captures are repeatable. Instance masks: world 0x01, gun/arms 0x02, glass 0x04, fx 0x08.
  Shadow and bounce rays use the world mask only.
- The creature is rigid parts posed in `src/game/Creature.cpp` on a `CrawlPath`
  (`src/world/CrawlSurface.*`). Its Blender rig (`CREATURE_RIG`) is for renders only;
  the engine reads the rest pivots from the `fx_bone_*` markers. Creature render
  lighting: `bk_studio.creature_lights()`; black glossy armour only reads by its rim light.
- Hunters (`src/game/Hunter.*`) are stepped by `Game::stepWorld`. Only the window
  (`--creatures`) and the hunt/fight scenes spawn them; the walk, fire, shots and bench
  captures have none. They re-route only at cell centres; never let a path change move
  the creature (level_tests checks a 0.4 m-per-step limit).
- capture_check rejects flat frames, so a scene must not end on a solid black fade.
- Window movement (`Game::update`) is not what the scripted films run. Check it with
  `--scene weave` (the window's own update at `--step-hz`) and the "walking straight" unit
  test at several frame rates. Camera-only offsets (sway, bob) must never feed back into
  the position, and per-step easing must use `1 - exp(-rate*dt)`, not `min(1, rate*dt)`.
- Never mirror a basis in `Mat4::basis` (X × Y must equal Z). A mirrored instance flips
  the winding, and back-face culling hides it. If a run is
  stopped, its `Bulkhead.exe` can keep running and lock the exe for the next build:
  wait for it to finish.

## Conventions

- Code compiles with `/W4 /WX`. Keep it warning-free.
- `src/world` and `src/core/Image|Log` must stay free of D3D12 (they are linked into unit tests).
- Use `bh::Rng` (PCG32) for anything seeded. Never use `<random>` distributions: a seed must
  give the same ship everywhere. `maze_tests` prints `rng(1234).next()`; if that changes, every
  layout changes.
- Grid: 4 m cells, x east, y south (row). The maze stores east and south edges for each cell.
- Shaders: add an entry with `bulkhead_compile_shader()` in `CMakeLists.txt`. It produces
  `g_<Name>.h`, which is included directly.
- Third-party code comes in through FetchContent, pinned to a commit (stb at present; cgltf comes next).
